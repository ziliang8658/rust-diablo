## 详细差异分析

### 1. 边界区域差异（3328个）

**位置**: x >= 96 或 y >= 96 (最后16列和行)

**问题**: 
- C++使用值 `426`
- Rust使用值 `218` (Town默认piece)

**影响**: 
- 边界区域不参与实际渲染，影响较小
- 但可能影响某些边界检查逻辑

**建议**: 
- 检查C++中426的含义
- 确认Rust是否应该使用426而不是218

### 2. Sector2s差异（4个）

**位置**: 
- (48, 20): C++=1170, Rust=1174
- (49, 20): C++=1171, Rust=1175
- (48, 21): C++=1172, Rust=1176
- (49, 21): C++=1173, Rust=1177

**模式**: Rust值比C++值大4

**可能原因**: 
- TIL数据索引偏移
- MegaTile到MicroTile转换时的索引问题

### 3. Sector3s差异（27个）

#### 3.1 位置(16-17, 68-71) - 7个差异

**差异值**: +7或+8 (C++值比Rust大)

**位置详情**:
- (16, 68): C++=1216, Rust=1209 (+7)
- (17, 68): C++=1217, Rust=1210 (+7)
- (16, 69): C++=1218, Rust=1211 (+7)
- (17, 69): C++=1219, Rust=1212 (+7)
- (16, 70): C++=1213, Rust=1205 (+8)
- (17, 70): C++=1214, Rust=1206 (+8)
- (16, 71): C++=1215, Rust=1207 (+8)

#### 3.2 位置(36-45, 78-79) - 20个差异 ⚠️ **严重问题**

**问题**: Rust加载了错误的大值（1236-1255），而C++是正确的（0-14）

**位置详情**:
```
(36-45, 78): C++值: 0,12,12,8,0,12,12,0,0,0
            Rust值: 1236,1237,1240,1241,1244,1245,1248,1249,1252,1253

(36-45, 79): C++值: 2,14,14,10,2,14,14,2,2,2
            Rust值: 1238,1239,1242,1243,1246,1247,1250,1251,1254,1255
```

**可能原因**:
- 数据加载时索引错误
- 某个sector的数据被错误地写入到这个位置
- 可能是sector3s加载时的偏移计算错误

### 4. Sector1s差异（2个）

**位置**: 
- (46, 78): C++=1, Rust=547
- (46, 79): C++=3, Rust=548

**问题**: Rust加载了错误的大值（547/548），而C++是正确的（1/3）

**可能原因**: 
- sector1s和sector3s边界处的数据覆盖问题
- 加载顺序导致的覆盖

## 关键发现

### ✅ 正确的部分

1. **Sector4s完全一致**: 说明基本的加载逻辑是正确的
2. **levelPieceId=290位置一致**: 
   - (13, 40): C++=290, Rust=290 ✓
   - (15, 44): C++=290, Rust=290 ✓
   - (71, 34): C++=290, Rust=290 ✓

### ❌ 需要修复的问题

1. **边界区域默认值**: Rust应该使用426而不是218
2. **Sector3s位置(36-45, 78-79)**: 加载了错误的数据
3. **Sector1s位置(46, 78-79)**: 加载了错误的数据
4. **Sector2s位置(48-49, 20-21)**: 索引偏移问题

## 修复建议

### 优先级1: 修复Sector3s和Sector1s的错误数据

这些位置的错误值（1236-1255, 547-548）明显超出了正常范围，可能导致渲染错误。

**检查点**:
1. `load_sector_to_dpiece`函数中的偏移计算
2. sector3s和sector1s的加载顺序
3. 边界检查逻辑（确保不会越界写入）

### 优先级2: 修复边界区域默认值

**检查点**:
1. C++中426的含义（可能是特殊的边界标记）
2. Rust的`load_dun_to_dpiece`函数中的默认值初始化

### 优先级3: 修复Sector2s的索引偏移

**检查点**:
1. TIL数据的索引计算
2. MegaTile到MicroTile的转换逻辑
