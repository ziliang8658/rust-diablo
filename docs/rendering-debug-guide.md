# 渲染层Debug指南

## 概述

当游戏画面出现渲染错误时，使用渲染层debug开关可以帮助你快速定位问题出现在哪一层。

本系统基于Diablo 1的两阶段渲染架构：
- **Phase 1: Floor Layer（地板层）** - 渲染地板瓦片
- **Phase 2: Wall Layer（墙体层）** - 渲染墙体和上层内容
- **Entity Layer（实体层）** - 渲染玩家、怪物等实体

## 快捷键

### 渲染层控制
- **F4** - 切换地板层显示（Floor Layer ON/OFF）
- **F5** - 切换墙体层显示（Wall Layer ON/OFF）
- **F6** - 切换实体层显示（Entity Layer ON/OFF）
- **F7** - 切换调试信息显示（Debug Info ON/OFF）
- **F8** - 重置所有层（恢复默认状态）

### 其他Debug工具
- **I** - 打印玩家当前位置的瓦片信息
- **F3** - 切换DirectRenderer模式（C++风格渲染）

## 使用方法

### 场景1：发现未知的红色像素

**问题**：画面中出现了不应该存在的红色区域

**Debug步骤**：
1. 按 **F5** 关闭墙体层
   - 如果红色消失 → 问题在墙体层
   - 如果红色依然存在 → 继续下一步

2. 按 **F4** 关闭地板层
   - 如果红色消失 → 问题在地板层
   - 如果红色依然存在 → 可能是背景或调色板问题

3. 按 **F8** 重置所有层，然后按 **F4** 只关闭地板层
   - 这样可以单独查看墙体层

### 场景2：某些图块没有渲染（如铁栅栏）

**问题**：铁栅栏或其他结构没有显示

**Debug步骤**：
1. 按 **F4** 关闭地板层
   - 检查铁栅栏是否在墙体层中渲染
   - 如果看到铁栅栏 → 说明墙体层渲染正常，但被地板层覆盖了（层级问题）

2. 按 **F8** 重置，然后按 **F6** 关闭实体层
   - 检查铁栅栏是否被玩家遮挡

3. 移动玩家到铁栅栏位置，按 **I** 查看瓦片信息
   - 检查tile ID、frame索引、透明度标志等
   - 对比C++原版的相同位置数据

### 场景3: 拖影/残影问题（正常现象）

**问题**：只显示某一层时，移动会出现拖影

**答案**：**这是正常现象！不是bug！**

**原理说明**：
- Diablo原版**故意不清除**帧缓冲（性能优化）
- Floor层负责"覆盖"上一帧的内容
- 只显示Wall层时，上一帧的内容会保留
- 这是设计特性，不是错误

**验证方法**：
1. 按 **F8** 重置所有层
2. 所有层都开启时，不应该有拖影
3. 如果所有层开启仍有拖影 → 说明某些tile没有正确渲染

### 场景4：透明度处理错误

**问题**：某些应该透明的区域显示为不透明，或反之

**Debug步骤**：
1. 按 **F5** 单独查看墙体层
   - 检查墙体层的透明度是否正确

2. 按 **F4** 单独查看地板层
   - 检查地板层是否有错误的透明像素

3. 按 **F8** 重置，观察两层叠加后的效果
   - 对比C++原版画面，找出差异

## 常见渲染问题排查流程

### 流程图

```
发现渲染问题
    ↓
1. 关闭墙体层（F5）
    ↓
问题是否消失？
    ├─ 是 → 问题在墙体层
    │       ↓
    │       检查：
    │       - 墙体瓦片ID是否正确
    │       - 透明度掩码是否正确
    │       - 渲染顺序是否正确
    │
    └─ 否 → 关闭地板层（F4）
            ↓
        问题是否消失？
            ├─ 是 → 问题在地板层
            │       ↓
            │       检查：
            │       - 地板瓦片ID是否正确
            │       - 调色板映射是否正确
            │       - CEL解码是否正确
            │
            └─ 否 → 关闭实体层（F6）
                    ↓
                问题是否消失？
                    ├─ 是 → 问题在实体层
                    └─ 否 → 问题在背景或系统层面
                            （调色板、帧缓冲清理等）
```

## 技术细节

### 渲染层架构

```rust
// RenderDebugFlags 结构体
pub struct RenderDebugFlags {
    pub render_floor: bool,      // 地板层开关
    pub render_walls: bool,       // 墙体层开关
    pub render_entities: bool,    // 实体层开关
    pub show_debug_info: bool,    // 调试信息开关
}
```

### 代码位置

- **Debug标志定义**: `src/debug.rs`
- **Game层集成**: `src/game.rs` - `handle_keydown()` 方法
- **World层渲染**: `src/world/mod.rs` - `render_with_texture_manager()` 和 `render_with_direct_renderer()` 方法

### 渲染逻辑

**地板层渲染**（Phase 1）：
```rust
if is_floor && debug_flags.render_floor {
    // 渲染地板瓦片（blocks 0-1）
    self.draw_floor_at(...);
}
```

**墙体层渲染**（Phase 2）：
```rust
if debug_flags.render_walls {
    // 渲染墙体瓦片（blocks 2-15）
    self.draw_cell_at(...);
}
```

**实体层渲染**：
```rust
if debug_flags.render_entities {
    // 渲染玩家、怪物、NPC等
    self.render_entities(...);
}
```

## 扩展功能建议

未来可以添加的debug功能：

1. **颜色标记模式**：给不同层用不同颜色标记
2. **边界框显示**：显示每个瓦片的边界框
3. **逐帧步进**：按空格键前进一帧，方便逐帧分析
4. **像素级对比**：导出当前帧与原版C++的帧进行像素对比
5. **热重载瓦片**：修改CEL文件后不重启即可重新加载
6. **性能分析**：显示每层的渲染时间

## 注意事项

1. **性能影响**：关闭某一层渲染会略微提高帧率，但不应该有明显差异
2. **保存状态**：debug标志不会保存，重启游戏后会恢复默认状态
3. **兼容性**：debug功能在DirectRenderer和TextureManager两种渲染模式下都可用

## 示例：定位红色像素问题

假设你发现画面左上角有一个不应该存在的红色像素块：

```bash
# 步骤1：启动游戏
cargo run --release

# 步骤2：按F4关闭地板层
# 观察：红色像素依然存在

# 步骤3：按F8重置，然后按F5关闭墙体层
# 观察：红色像素消失了！

# 结论：问题在墙体层

# 步骤4：移动到红色像素位置，按I查看瓦片信息
# 输出：
# Tile at (10, 15): type=Wall, frame=123, transparency=Left

# 步骤5：检查frame 123的解码数据
# 可能原因：
# - frame索引越界
# - 调色板索引错误
# - CEL解码bug
```
