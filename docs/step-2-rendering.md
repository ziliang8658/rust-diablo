# Step 2: 基础渲染系统和坐标系统

## 设计思路

第二步在基础框架之上实现了渲染和坐标系统，让游戏能够显示可视化的内容。主要实现了：

1. **坐标系统**：建立了 2D 坐标体系，支持世界坐标和屏幕坐标
2. **渲染系统**：实现了基本的图形绘制功能
3. **实体系统**：创建了简单的实体结构，为游戏对象打基础
4. **游戏世界**：实现了基于网格的地图系统
5. **交互控制**：添加了 WASD/方向键控制玩家移动

这些功能参考了原始代码中的：
- `engine/render/scrollrt.cpp` - 渲染系统
- `levels/gendung.h` - 地图生成和网格系统
- `player.h` - 实体位置和移动

## 实现细节

### 1. 模块结构

```
src/
```

### 2. 核心组件

#### `math::Point`
- 表示 2D 坐标位置
- 支持基本的向量运算（加减）
- 提供距离计算
- 可与 SDL2 的 Point 互转

```rust
let pos = Point::new(100, 200);
let delta = Point::new(10, 0);
let new_pos = pos + delta;  // (110, 200)
```

#### `math::Rect`
- 表示矩形区域
- 支持碰撞检测
- 提供中心点计算
- 用于实体边界框

```rust
let rect = Rect::new(x, y, width, height);
let contains = rect.contains(point);
let intersects = rect.intersects(&other_rect);
```

#### `renderer::Color`
- RGB 颜色表示
- 预定义常用颜色（BLACK, WHITE, RED 等）
- Diablo 风格的颜色（DARK_GRAY, DARK_RED 等）

#### `entity::Entity`
- 游戏实体基类
- 包含位置、大小、颜色
- 支持移动和碰撞检测
- 实体类型区分（Player, Monster, Item, Object）

#### `world::World`
- 基于网格的地图系统
- 20×15 的瓦片网格（32×32像素/瓦片）
- 管理所有实体
- 处理世界渲染

#### 扩展的 `Engine`
新增绘图方法：
- `clear_with_color()` - 用指定颜色清屏
- `draw_rect()` - 绘制填充矩形
- `draw_rect_outline()` - 绘制矩形边框
- `draw_line()` - 绘制线段
- `draw_point()` - 绘制点

### 3. 游戏循环增强

**初始化**：
```rust
// 创建 20×15 的瓦片世界
let mut world = World::new(20, 15, 32);

// 在中心创建玩家
let player = Entity::create_player(Point::new(320, 240));
world.add_entity(player);
```

**输入处理**：
- `W/↑` - 向上移动
- `S/↓` - 向下移动
- `A/←` - 向左移动
- `D/→` - 向右移动
- `ESC` - 退出游戏

**更新**：
```rust
fn update(&mut self) -> Result<()> {
    self.world.update();  // 更新所有实体
    Ok(())
}
```

**渲染**：
```rust
fn render(&mut self) -> Result<()> {
    self.engine.clear()?;
    self.world.render(&mut self.engine)?;  // 渲染世界和实体
    self.engine.present();
    Ok(())
}
```

### 4. 技术亮点

**坐标系统**：
- 使用整数坐标（i32）避免浮点误差
- 统一的坐标表示，便于计算和转换

**渲染分层**：
1. 清屏（背景色）
2. 绘制地图瓦片
3. 绘制瓦片边框（网格线）
4. 绘制实体

**实体系统设计**：
- 简单但可扩展的设计
- 为后续的组件系统（ECS）打基础
- 支持不同类型的实体

## 技术要点

### Rust 特性使用

1. **模块化设计**：清晰的模块划分，职责分离
2. **类型安全**：使用枚举表示实体类型和瓦片类型
3. **所有权系统**：实体由 World 拥有，避免悬空引用
4. **错误处理**：统一使用 `Result` 处理可能的错误
5. **运算符重载**：为 Point 实现 `Add` 和 `Sub` trait

### 设计模式

1. **组合优于继承**：实体包含位置、大小等属性，而非继承
2. **单一职责**：每个模块专注于特定功能
3. **开闭原则**：易于扩展新的实体类型和瓦片类型

## 遇到的问题和解决方案

### 问题 1：坐标系统选择
- **问题**：是使用浮点数还是整数坐标？
- **解决**：使用 i32 整数坐标，避免浮点误差，像素对齐更准确

### 问题 2：实体管理
- **问题**：实体存储在哪里？如何高效访问玩家？
- **解决**：存储在 World 中，Game 保存玩家索引快速访问

### 问题 3：渲染顺序
- **问题**：如何保证正确的绘制层次？
- **解决**：先绘制地图，再绘制实体，未来可添加 z-order
