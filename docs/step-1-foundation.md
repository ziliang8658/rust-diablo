# Step 1: 基础游戏框架

## 设计思路

第一步的目标是建立一个最基础的游戏框架，为后续开发打下坚实的基础。这个框架需要包含：

1. **项目结构**：建立清晰的Rust项目结构，便于后续扩展
2. **游戏循环**：实现标准的游戏循环（事件处理 → 更新 → 渲染）
3. **窗口和渲染**：使用SDL2创建窗口和基础的渲染系统
4. **输入处理**：处理键盘和鼠标输入事件

这个框架参考了原始代码中的核心结构：
- `main.cpp` → `DiabloMain` → `RunGameLoop` 的流程
- `engine/dx.cpp` 中的窗口和渲染初始化
- `diablo.cpp` 中的事件处理逻辑

## 实现细节

### 1. 项目结构

```
rust-diablo/
├── Cargo.toml          # Rust项目配置文件
├── src/
│   ├── main.rs        # 程序入口
│   ├── game.rs        # 游戏循环和状态管理
│   └── engine.rs      # 引擎层（SDL2封装）
└── docs/
    └── step-1-foundation.md  # 本文档
```

### 2. 核心模块

#### `main.rs`
- 程序入口点
- 创建Game实例并运行游戏循环

#### `game.rs`
- `Game` 结构体：管理游戏状态
- `run()` 方法：主游戏循环
- `process_events()`：处理SDL2事件
- `update()`：游戏逻辑更新（当前为空，为后续扩展预留）
- `render()`：渲染当前帧（当前只清屏，为后续扩展预留）

#### `engine.rs`
- `Engine` 结构体：封装SDL2功能
- 窗口创建：640x480分辨率（Diablo原始分辨率）
- 渲染管理：Canvas管理和清屏/呈现操作
- 事件泵：提供事件处理接口

### 3. 技术选型

- **SDL2**：跨平台的多媒体库，用于窗口、输入和渲染
- **anyhow**：错误处理库，提供简洁的错误处理

### 4. 代码量统计

- `main.rs`: ~15行
- `game.rs`: ~120行
- `engine.rs`: ~100行
- 总计：约235行（符合500行左右的要求，为后续扩展预留空间）

## 技术要点

1. **Rust的所有权系统**：使用`&mut`来管理SDL2资源的访问
2. **错误处理**：使用`anyhow::Result`进行统一的错误处理
3. **模块化设计**：将游戏逻辑和引擎层分离，便于维护和测试
4. **可扩展性**：所有关键方法都预留了扩展空间，便于后续添加功能
