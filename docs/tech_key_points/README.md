## 📖 文档说明

### 为什么需要单独的技术要点文档？

**MASTER_PLAN.md** 是总体纲要，侧重于：
- 整体规划和步骤安排
- 功能清单和代码量估算
- 参考代码位置
- 测试要求概述

**tech_key_points/** 中的文档侧重于：
- 技术实现的详细细节
- 文件格式规范和算法
- 完整的代码实现示例
- 深入的技术解释

这样的组织方式使得：
- 📋 总体规划保持简洁易读
- 🔧 技术细节方便深入查阅
- 📚 文档结构层次分明

## 🎯 使用指南

### 开发流程

1. **规划阶段** → 查看 [MASTER_PLAN.md](../MASTER_PLAN.md)
   - 了解整体步骤安排
   - 确定当前Step的目标

2. **实现阶段** → 查看对应的技术要点文档
   - 深入理解技术细节
   - 参考代码实现示例
   - 按照文档实现功能

3. **测试阶段** → 参考文档中的测试部分
   - 编写单元测试
   - 集成测试
   - 性能测试

## 📝 文档更新规则

1. **何时创建新的技术要点文档？**
   - Step的实现细节超过500行
   - 涉及复杂的算法或格式规范
   - 需要大量代码示例
   - 有多个子系统需要详细说明

2. **文档命名规范**
   - 格式：`step{N}-{feature-name}.md`
   - 例如：`step5-resource-formats.md`
   - 使用小写字母和连字符

3. **文档内容要求**
   - 必须包含：文件格式规范、Rust实现代码、测试要求
   - 代码示例要完整可运行
   - 包含必要的图表和说明
   - 引用原版代码位置
