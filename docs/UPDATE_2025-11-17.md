### 3. 测试指南 (TESTING_GUIDE.md)

**目的：** 建立测试驱动开发（TDD）标准

**主要内容：**

#### 测试原则
- 测试金字塔：80% 单元测试、15% 集成测试、5% E2E测试
- 每个Step必须包含测试
- 遵循 Red-Green-Refactor 流程

#### 测试类型

**1. 单元测试**
```rust
#[cfg(test)]
mod tests {
    #[test]
    fn test_point_addition() {
        let p1 = Point::new(10, 20);
        let p2 = Point::new(5, 3);
        assert_eq!(p1 + p2, Point::new(15, 23));
    }
}
```

**2. 集成测试**
```rust
// tests/game_integration_test.rs
#[test]
fn test_player_movement() {
    let mut game = Game::new().unwrap();
    game.move_player(1, 0);
    assert_ne!(game.player_position(), initial_pos);
}
```

**3. 手动测试场景**
```rust
// examples/test_combat.rs
fn main() -> Result<()> {
    let mut game = Game::new()?;
    game.spawn_monster("zombie", Point::new(150, 100));
    game.run()
}
```

**4. 性能测试**
```rust
// benches/pathfinding_benchmark.rs
fn benchmark_pathfinding(c: &mut Criterion) {
    c.bench_function("a_star_10x10", |b| {
        b.iter(|| a_star(black_box(&map), ...))
    });
}
```

#### 测试覆盖率目标

| 系统类型 | 覆盖率目标 |
|---------|-----------|
| 核心系统 | ≥ 85% |
| 一般系统 | ≥ 70% |
| UI系统 | ≥ 60% |

#### 测试工具

**运行测试：**
```bash
# 单元测试
cargo test

# 集成测试
cargo test --test '*'

# 性能测试
cargo bench

# 代码覆盖率
cargo llvm-cov --html
```

**依赖配置：**
```toml
[dev-dependencies]
criterion = "0.5"

[[bench]]
name = "pathfinding_benchmark"
harness = false
```

### 3. 测试驱动开发

**要求：**
- **每个Step必须包含测试**
- 测试先于实现（TDD）
- 4种测试类型都要覆盖

**集成到开发流程：**
1. **文档先行** → 设计文档
2. **测试先行** → 编写测试用例
3. **实现功能** → 通过测试
4. **代码审查** → 审查测试覆盖率
5. **总结文档** → 包含测试报告

**工具支持：**
- 单元测试：`cargo test`
- 性能测试：`criterion`
- 覆盖率：`cargo-llvm-cov`
- CI/CD：GitHub Actions配置
